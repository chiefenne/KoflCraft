# M1 box-clipped Voronoi reference

The initial library covers the geometry, construction, reconciliation, validation, and export stages in [section 15](../docs/requirements.md#15-immediate-m1-engineering-sequence). [`generate_mesh`](../crates/mesh-engine/src/assembly.rs) takes a box and an ordered slice of interior sites. [`clipped_voronoi`](../crates/mesh-algorithms/src/voronoi.rs) exposes the candidate cells for inspecting the construction stage.

For sites $p$ and $q$, the condition $\|x-p\|^2 \le \|x-q\|^2$ simplifies to $(q-p)\cdot(x-(p+q)/2) \le 0$. Each cell starts as the box and intersects the half-space for every other site in input order. Taveira et al. describe exhaustive bisector clipping as the baseline for independently constructed cells. [Taveira et al., §4.1](https://arxiv.org/html/2605.06408v1#S4.SS1)

The Rust clipper works on indexed polygon loops. It computes one intersection per crossing edge, clips the incident polygons, and traces the exposed edges in reverse to form the outward-wound cap. Box faces retain their axis-side tags. Cap faces record the index of the other site so a subsequent assembly pass can identify both sides of each internal face.

Clipping runs in translated coordinates scaled by the longest box side, with a signed-distance tolerance of 64 binary64 machine epsilons. Comparisons within that tolerance treat points as on-plane. Input validation requires strictly interior sites, a minimum site separation above twice the tolerance, and box extents above that same threshold. A cut that fails to produce a single closed cap is an error. Cell vertices are returned in the original coordinates and coincident vertices after conversion are rejected. This floating-point baseline has a finite resolution. Exact plane predicates remain a research direction under OPEN-06. [Nehring-Wirxel et al., 2025](https://www.graphics.rwth-aachen.de/publication/03355/)

The assembly pass welds local vertices within `2048 × f64::EPSILON` times the box's longest side. It uses the first matching coordinate in input order and rejects ambiguous welds and repeated indices within a cell. Bisector faces are matched by site pair and must have identical vertex rings under cyclic reversal. The packed [`Mesh` contract](../crates/mesh-core/src/mesh.rs) stores each shared face once with owner-outward winding and derives both cells’ face lists from owner and neighbour indices.

[`validate_mesh`](../crates/mesh-quality/src/lib.rs) accepts packed connectivity directly. It checks planar, convex polygons, consistent orientation, convex cell shells, opposite edge uses, six exterior patch areas, and total volume. Each convex cell shell contributes an outward boundary. Shared faces cancel, so the surviving boundary covers the prescribed box with multiplicity one within the stated tolerances. Plane distances allow `8192 × f64::EPSILON` times the longest box side. Area and volume conservation use relative tolerance `1e-10`. Inputs whose coordinates or metrics fall outside the supported floating-point resolution can produce a validation error.

Face area and centroid come from a triangle fan. Cell volume and centroid come from tetrahedra formed by those triangles and the mean of the cell vertices. Non-orthogonality measures the angle between the face normal and the centroid-to-centroid direction. Skewness divides the face centroid's distance from that line's face-plane intersection by the centroid separation. On boundary faces the angle uses the direction from the owner centroid to the face centroid, and skewness uses its tangential offset divided by that direction's length.

The [export writers](../crates/mesh-io/src/lib.rs) validate before emitting bytes to caller-provided streams. VTU stores VTK polyhedron cells with outward-wound face streams for both incidences of an internal face. [VTK XML file format](https://docs.vtk.org/en/v9.6.1/vtk_file_formats/vtkxml_file_format.html)

The [Gmsh writer](../crates/mesh-io/src/gmsh.rs) uses first-order tetrahedra for stable Gmsh 4.x. It triangulates each face from its first vertex, matching the validator’s volume calculation. If a vertex fan contains a flat triangle, the writer joins each edge to the face centroid instead. Both cells bordering an internal face share the same triangles with opposite winding. The writer joins those triangles to the cell centroid and checks positive tetrahedral volumes and conservation in each original cell before serialization. MSH 2.2 stores the six named surface groups and records the original cell through the elementary volume tag. [Stable Gmsh element types](https://gmsh.info/doc/texinfo/gmsh.html#MSH-file-format), [Gmsh MSH 2.2 format](https://gmsh.info/doc/texinfo/gmsh.html#MSH-file-format-version-2-_0028Legacy_0029)

Run `cargo test --locked --workspace --all-targets` to check analytic cuts, rectangular boxes at several scales, and 16-, 64-, and 256-site lattices and clustered fixtures. The tests check local half-space containment, global face matching and boundary closure, positive volumes, conservation, repeatable connectivity, and both export formats with independent test parsers. The [M1 usage guide](../docs/m1-usage.md) covers the workspace entry points and evidence format.
